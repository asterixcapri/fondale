# 07 — `define-object`

**What to build:** the third fabrication skill, generated from the shared source
established in 06, with the parts specific to an Object on top.

An Object has no absolute size: it exists in proportion to the Character who
carries it and the Scene it sits in, so its target is derived from its declared
size in world units like everything else — a lantern must not end up the size of
a door. Its Inventory Appearance is a separate matter: it belongs to the UI scale
against the Logical Resolution, is unaffected by Perspective Scale, and is judged
for legibility in the bag rather than for consistency with the world artwork.

Replaces the existing `define-object`.

**Blocked by:** 06

**Status:** ready-for-human

## Comments

Built as the third pair of source documents under `skills/shared/sources/`
(`define-object.md` and `define-object.values.md`), so `skills/define-object/SKILL.md`
is now generated by `tools/generate-skill-documents.mjs` and guarded by
`tools/verify-generated-skill-documents.mjs`; both discover a skill from the
sources directory, so no list needed editing. The old skill's `agents/openai.yaml`
and `references/object-package.md` are removed and the normaliser is carried into
`skills/define-object/scripts/`, matching the layout tickets 05 and 06 settled.

On the acceptance criteria:

- The in-Scene target is the Object's declared size in `docs/game/assets.md`
  times the pixels per world unit in `docs/game/world.md`, the same arithmetic
  every other asset of the world uses, and it binds every Appearance and every
  Animation frame so a state change cannot resize the Object.
- Recompose takes the Character who carries the Object as the figure standing in
  `preview.png`, rather than whichever Character is nearest, and Approve names
  the two silhouettes against each other as the judgement being made.
- The Inventory Appearance has its own target — the Inventory Appearance Size
  from the `## UI scale` section of `docs/game/world.md` — is squared for the
  Engine, is never touched by Perspective Scale, and gets no row in the register,
  so a UI number never lands in a column of world numbers.
- The cycle appears only as `{{ fabrication-cycle }}`; the skill's own prose is
  the two source documents and nothing is hand-copied from the other two skills.
- No reference to `docs/agents/visual-direction.md` or to anything else in this
  repository survives: the skill reads the host game's `docs/game/` and the
  Engine's contract from `node_modules/@asterixcapri/fondale/docs/public/`.
