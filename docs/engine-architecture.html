Come una definizione diventa un’avventura giocabile

L’Engine è organizzato per Engine Capability: ogni modulo possiede le regole del proprio dominio dall’authoring al runtime. CoreSession coordina tempo e stato; browser e storage restano adapter tecnici.

Il flusso completo

dati immutabili coordinamento policy di capability adapter tecnico
1

Authoring → Game Project

L’Author compone normali dati TypeScript in file focalizzati, usando i type pubblici e satisfies. Non esistono builder defineX: Game Project è la raccolta dichiarativa di Project Identity, Project Version, Game Definition e Game Setting.

typed Game Definition + Game Settings
2

startGame → validazione e compilazione

startGame innesca la validazione distribuita: ogni capability verifica i propri invarianti e Game Project aggrega gli Authoring Diagnostic. Un risultato valido applica i default e crea una copia privata profondamente immutabile, senza modificare i dati dell’Author.

Game Project → private compiled project
3

Avvio → CoreSession

Dopo la compilazione, startGame offre Continue per un Continuation State valido oppure New Game, controlla browser e Runtime Asset e crea gli adapter. CoreSession crea o ripristina il Game State canonico e avvia il logical tick.

compiled project + validated continuation or new state
4

Input fisico → intenzione dichiarata

Pointer e tastiera vengono tradotti in input di sessione o intenzioni HUD. L’adapter non sceglie Command Case, percorsi, conseguenze o avanzamento di Sequence.

DOM / pointer / keyboard → CoreInput
5

Tick → decisione → commit atomico

CoreSession consuma la coda in ordine, determina la Game Activity dominante, chiede decisioni alle capability e applica tutte le Game Operation insieme. Un fallimento conserva lo stato precedente.

immutable state views → decisions → next Game State
6

Fatti derivati → presentazione

World, Animation, Camera e HUD producono fatti coerenti dallo stesso stato. PixiJS e DOM costruiscono sprite e controlli accessibili senza reinterpretare la Game Definition.

snapshot + CoreEffect + presentation facts

CoreSession: coordinatore deterministico

Possiede

Game State canonico, logical tick, coda input, ciclo di vita, Game Activity dominante e commit atomico.

Delega

Command resolution a Interaction, movimento a World, flusso temporale a Sequence, Character Knowledge a Knowledge-Driven Dialogue e visual facts alle capability di presentazione.

Garantisce

Snapshot ed effetti difensivi, ordine riproducibile, restore esatto e nessun riferimento mutabile allo stato globale.

1 · QueueInput copiati e accodati.
2 · RouteLa Game Activity decide chi riceve l’input.
3 · DecideLe capability restituiscono risultati espliciti.
4 · CommitIl nuovo Game State sostituisce il precedente in modo atomico.

Chi possiede che cosa

Game Project

Dati dichiarativi dell’Author; internamente coordina compilazione, Project Identity/Version e aggregazione degli Authoring Diagnostic.

World

Scene Space, presenza, geometria, navigazione, Motion e Scene Passage.

Detail View

Immagine presentata al posto del mondo, Hotspot locali senza Approach Point e risoluzione immediata dei Command.

Interaction

Noun, Command, condizioni, Player Intent, Inventory e conseguenze.

Knowledge-Driven Dialogue

Narrative Fact, Character Knowledge, validazione dei riferimenti e apprendimento monotono; World non possiede questa policy.

Sequence

Step, ordine, concorrenza, Cue, Line, Narration, Choice, branch e Skip Outcome.

Animation

Appearance, Animation Role, frame, durata, Cue visuali e Visual Anchor.

Camera

Follow del Player e regia cut/move/hold/follow indipendente da PixiJS.

HUD

Contextual Action, Command Preview, Inventory, Choice, narrative e overlay di sistema.

Save

Snapshot logico, compatibilità, validazione e restore; non possiede localStorage.

Game Session

CoreSession e il coordinamento deterministico, senza duplicare policy specialistiche.

Flussi di comunicazione consentiti

Le frecce indicano chi può chiedere una decisione o consegnare un fatto. Non autorizzano l’accesso ai dettagli privati: ogni scambio attraversa l’interfaccia dichiarata del proprietario.

  1. Browser adapter → Game Session

    DOM, pointer e tastiera traducono gli eventi fisici senza scegliere conseguenze di dominio.

    CoreInput · HUD intention
  2. Game Session → Interaction / World / Sequence / Knowledge-Driven Dialogue

    CoreSession passa viste immutabili e coordina i risultati espliciti restituiti dai proprietari.

    state view · decision · Game Operation
  3. Sequence → Animation / World / Camera

    Sequence condivide la timeline del Direction Step; ciascuna capability conserva la propria semantica.

    direction timing · Animation Cue · local tick
  4. Capability → browser adapter

    World, Animation, Camera e HUD espongono fatti già risolti che PixiJS e DOM si limitano a presentare.

    presentation facts · CoreEffect
  5. Game Session ↔ Save

    La sessione consegna stato committed; Save produce o valida uno snapshot. Il restore crea uno stato completo soltanto dopo una validazione riuscita.

    Game State · Save Snapshot · validation result
  6. startGame → Game Project ↔ capability validators

    L’avvio innesca la compilazione interna; Game Project distribuisce viste strette delle definizioni e aggrega gli Authoring Diagnostic attribuiti, senza duplicare le regole.

    validation view · Authoring Diagnostic[] · compiled copy

Direction Step: una regia, più proprietari

Sequence calcola una sola timeline locale. Animation, World e Camera ricevono la stessa interpretazione e applicano il significato delle rispettive direzioni.

Sequence coordina “quando”.
Cue, start tick, local tick e completamento sono indipendenti dal browser.
Le capability decidono “che cosa”.
Animation seleziona frame e durata; World governa Motion; Camera produce il focus.
Concorrenza esplicita.
Animation, Motion e Camera possono essere attive nello stesso step con lo stesso tempo locale.
Fine deterministica.
Lo step termina quando finiscono tutte le direzioni finite oppure scade la durata authored, al primo dei due eventi.

Save Snapshot e Continuation State restano distinti

Game State committed

CoreSession espone una copia difensiva dei fatti canonici necessari, inclusa la Character Knowledge di ogni Character.

⇄

Continuation State nel browser

localStorage associa l’ultimo Save Snapshot validato all’identità della memoria del Dialogue Provider. Continue recupera entrambi; New Game sostituisce l’associazione.

Uno snapshot incompatibile viene rifiutato con diagnostica strutturata e lascia disponibile soltanto New Game. Il Player non gestisce salvataggi nominati o storici.

Dipendenze consentite

Interfacce, non dettagli.
Una capability importa un’altra capability soltanto dal suo index.ts dichiarato.
Viste strette e immutabili.
startGame copia e congela il Game Project valido; ogni modulo interno riceve soltanto la propria vista e nessun riferimento mutabile dell’Author o del Game State.
Niente contenitore shared.
La policy resta presso il proprietario; il controllo strutturale impedisce scorciatoie orizzontali.
Un solo package root.
L’Author importa da @asterixcapri/fondale; la struttura interna non diventa contratto pubblico.

Adapter tecnici

PixiJS

Texture, sprite, canvas e applicazione dei world/camera facts.

DOM e input

Controlli accessibili, focus, pointer, tastiera, timer e preferenze locali.

Asset e storage

Caricamento, audio e localStorage; errori tecnici diventano diagnostic, non regole di dominio.

Glossario visuale minimo

Game Project
Il contenuto e le impostazioni che definiscono una singola avventura.
Game Session
Una esecuzione isolata del progetto, coordinata da CoreSession.
Character Knowledge
Riferimenti ai Narrative Fact disponibili a un Character nella Game Session.
Game State
I fatti canonici committed che determinano come il mondo può evolvere.
Game Activity
L’attività dominante: Player Intent, Sequence o risposta temporanea.
Game Operation
Una richiesta validata che cambia lo stato in modo atomico.
Player Intent
L’esecuzione di un Command, incluso l’eventuale avvicinamento.
Direction Step
Uno step sequenziale che dirige più Animation, Motion e Camera concorrenti.
Presentation fact
Un dato derivato e immutabile che un adapter può disegnare senza policy.
Authoring Diagnostic
Una spiegazione strutturata, attribuita al proprietario della regola.
Adapter
L’integrazione tecnica sostituibile posta a un seam dichiarato.
